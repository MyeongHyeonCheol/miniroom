# 세션 저장, 유지 기간, 동시 로그인 1곳 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 로그인 세션을 PostgreSQL에 저장해 재시작에도 유지하고, 7일 유휴 만료, 계정당 1곳 로그인(새 로그인이 이전 것을 끊음), 동시 첫 로그인 500 수정, 비로그인 세션 생성 막기.

**Architecture:** Spring Session JDBC(`spring_session` 테이블, Flyway V2). 로그인 성공 처리기가 같은 `sub`의 다른 세션에 `replaced` 표시, `ReplacedSessionFilter`가 그 세션의 다음 요청을 무효화하고 `/api/**`에는 `401 {"reason":"replaced"}`. 사용자 저장은 `insert ... on conflict do update`. 통합 테스트는 compose `backend-test` 서비스가 실제 postgres의 `it` 스키마로 돌린다.

**Tech Stack:** 기존 + `spring-boot-starter-session-jdbc`. Redis 안 씀(사용자 승인 범위: "꼭 필요하지 않으면 안 넣어도 됨").

**Spec:** `docs/superpowers/specs/2026-10-01-login-design.md` + 이 대화에서 정한 값(대화 2026-10-01): 동시 로그인 1곳(새 로그인이 이전 것을 끊음), 마지막 활동 후 7일, 쿠키 수명 30일 상한.

## Global Constraints

- 커밋은 사용자가 요청할 때만. 비밀 값은 `.env`만.
- 세션 유휴 만료 `7d`, 세션 쿠키 `Max-Age` 30일(2592000), `HttpOnly`, `SameSite=Lax`.
- 스키마는 Flyway로만(`spring.session.jdbc.initialize-schema: never`).
- 단위 테스트는 이미지 빌드(`docker build --target build backend`), 통합 테스트는 `docker compose run --rm backend-test`. 통합 테스트는 JUnit 태그 `integration`, 기본 `test` 작업에서 빠진다.

## Review Focus

- 교체된 기기가 `/api` 대신 페이지 이동(`/oauth2/...`)을 해도 세션이 무효화되고 새 로그인이 정상 진행되는가 → Task 3 테스트 `replacedSessionIsInvalidatedOnAnyPath`.
- 새로 로그인한 세션 자신은 교체 표시를 받지 않는가 → Task 3 `keepOnlyLeavesCurrentSessionAlone`.
- 비로그인 `/api/me` 401이 세션 행을 만들지 않는가 → Task 2 `anonymousApiCallCreatesNoSession`.
- 동시 첫 로그인 10개 → 행 1개, 예외 없음 → Task 1 `concurrentFirstLoginsMakeOneRow`.
- 통합 테스트 데이터가 실제 `public` 스키마를 건드리지 않는가 → Task 0 `currentSchema=it`, Task 0 Step 4 확인.
